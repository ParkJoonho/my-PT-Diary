# AI 신발 추천 및 보행 분석

작성일자: 2026-07-28

## 1. 문서 목적

원본 앱에서 AI Hub 카드로는 따로 보이지만 실제 구현은 `/ai-analysis` 안에 섞여 있는 신발 추천/보행 분석 기능을 별도 기능으로 정리한다.

## 2. 원본 구현 기준

| 구분 | 내용 |
| --- | --- |
| AI Hub 카드 경로 | `/shoe-recommendation` |
| 실제 구현 위치 | `app/ai-analysis.tsx` 안의 `shoeImageBase64` 기반 분석 |
| 서버 처리 | `POST /api/ai/body-analysis` 내부 `gaitAnalysis` 결과 |
| QA 문서 | `2026-07-13/pt-diary-qa/ai-hub/my-pt-diary-qa-ai-hub-5-shoe-recommendation.md` |

## 3. 기능 범위

- 신발 밑창/뒤꿈치 사진 선택
- 체형 분석과 함께 보행 분석 수행
- 마모 패턴, 보행 유형, 아치/정렬 분석
- 신발 사이즈/발볼 추정
- 현재 보행 기준 추천 신발
- 교정 후 기준 추천 신발

## 4. 요구사항 및 원본 구현 현황

| ID | 요구사항·기대 동작 | 원본 구현 판단 | 현재 확인 내용 | 근거 파일 |
| --- | --- | --- | --- | --- |
| SR-001 | AI Hub 신발 추천 카드가 실제 기능으로 연결돼야 한다. | 미구현 | 카드는 `/shoe-recommendation`으로 가지만 실제 전용 화면이 없다. | `app/(tabs)/ai-hub.tsx`, `app/_layout.tsx` |
| SR-002 | 신발 사진만으로도 관련 기능을 시작할 수 있어야 한다. | 부분 구현 | 실제론 전신 사진이 필수고 신발 사진은 선택값이다. | `app/ai-analysis.tsx` |
| SR-003 | 신발 사진이 있으면 보행/마모/추천 결과를 함께 생성해야 한다. | 구현됨 | `gaitAnalysis`, `shoeSizeEstimate`, `shoeRecommendations`를 prompt로 강제한다. | `server/ai-routes.ts` |
| SR-004 | 결과는 현재 보행/교정 후, 일상/운동화 기준으로 나뉘어야 한다. | 구현됨 | UI 탭 전환으로 구조를 분리한다. | `app/ai-analysis.tsx`, `types/analysis.ts` |
| SR-005 | 추천 모델은 실제 구매 가능한 제품이어야 한다. | 부분 구현 | 프롬프트는 실제 브랜드/모델을 요구하지만 검증 로직은 없다. | `server/ai-routes.ts` |

## 5. 원본 구현에서 확인된 결함

| ID | 항목 | 현재 문제 |
| --- | --- | --- |
| SR-BUG-001 | 전용 진입 경로 미구현 | 카드 라우트는 있으나 전용 화면/라우트가 없다. |
| SR-BUG-002 | 입력 검증 부족 | 밑창 전체 노출, 좌우, 마모 판독 가능성, 사용 기간 등을 검증하지 않는다. |
| SR-BUG-003 | 민감 속성 추정 | 성별/연령대를 사진과 사이즈 추정으로 생성해 UI에 노출한다. |
| SR-BUG-004 | 추천 상품 현재성 검증 없음 | 제품, 가격, 구매 가능성, 재고를 확인하지 않는다. |
| SR-BUG-005 | 저장/재열람 분리 부족 | 기록은 body 타입에 함께 저장되며 신발 추천 전용 재열람 UI가 없다. |
| SR-BUG-006 | 인증 보호 부족 | 전신+신발 사진 분석을 비로그인 호출로도 실행할 수 있다. |
