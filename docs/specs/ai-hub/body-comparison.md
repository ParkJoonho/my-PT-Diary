# AI 전·후 사진 직접 비교

작성일자: 2026-07-28

## 1. 문서 목적

`/ai-analysis` 안에 함께 구현된 전·후 사진 직접 비교 기능을 별도 기능으로 정리한다.

## 2. 원본 구현 기준

| 구분 | 내용 |
| --- | --- |
| 진입 위치 | `app/ai-analysis.tsx` 내 comparison section |
| 비교 API | `POST /api/ai/body-comparison` |
| 저장 방식 | `analysisType: "body-comparison"`으로 `analysis_records` 저장 |
| 서버 구현 | `server/ai-routes.ts` |

## 3. 기능 범위

- Before / After 사진 각각 선택
- 선택 후 비교 분석 실행
- 전체 변화 등급/점수/요약
- 상체/코어/하체 변화
- 자세 변화
- 근육량/체지방 변화 추정
- 결과 저장

## 4. 요구사항 및 원본 구현 현황

| ID | 요구사항·기대 동작 | 원본 구현 판단 | 현재 확인 내용 | 근거 파일 |
| --- | --- | --- | --- | --- |
| BC-001 | 사용자는 전·후 사진 두 장을 골라야 비교를 시작할 수 있어야 한다. | 구현됨 | 두 장이 모두 있어야 비교 버튼이 동작한다. | `app/ai-analysis.tsx` |
| BC-002 | 서버는 두 장의 사진을 멀티모달 입력으로 비교 분석해야 한다. | 구현됨 | `Before`, `After` 두 이미지를 함께 LLM에 보낸다. | `server/ai-routes.ts` |
| BC-003 | 결과는 등급, 점수, 부위별 변화, 자세 변화, 추천을 반환해야 한다. | 구현됨 | JSON 구조를 프롬프트로 강제한다. | `server/ai-routes.ts` |
| BC-004 | 비교 결과는 기록으로 저장되어야 한다. | 부분 구현 | `body-comparison` 타입으로 저장하지만 실패를 안내하지 않는다. | `app/ai-analysis.tsx`, `server/ai-routes.ts` |
| BC-005 | 비교 결과는 사진 기반 추정이라는 사실을 드러내야 한다. | 미흡 | 화면은 비교 결과를 보여주지만 촬영 조건/동일 인물 확인 단계가 없다. | `app/ai-analysis.tsx` |

## 5. 원본 구현에서 확인된 결함

| ID | 항목 | 현재 문제 |
| --- | --- | --- |
| BC-BUG-001 | 동일 인물/시간 순서 검증 없음 | 사용자가 어떤 사진을 넣든 첫 장을 Before, 둘째를 After로 처리한다. |
| BC-BUG-002 | 촬영일/조건 확인 없음 | 시점, 조명, 자세 일관성, 촬영거리 같은 입력이 없다. |
| BC-BUG-003 | 저장 실패 비가시성 | 비교 결과 저장 실패를 사용자에게 알리지 않는다. |
| BC-BUG-004 | 상세 재열람 특화 부족 | `body-comparison` 전용 상세 렌더러가 없다. |

## 6. 마이그레이션 판단

| 항목 | 판단 |
| --- | --- |
| 마이그레이션 우선순위 | 중간 |
| 이유 | 원본에서 구현되어 있고 체형 분석 맥락과 연결되지만, 본체 분석·이력보다 후순위로 붙여도 흐름이 무너지지 않는다. |
| 구현 방식 | 원본과 같은 사진 2장 비교 구조를 유지하되, 결과를 body 본체와 별도 타입으로 저장한다. |

## 7. 이번 설계 기준 보정 포인트

| 항목 | 설계 기준 |
| --- | --- |
| 결과 고지 | 사진 기반 추정이며 동일 조건 비교가 아니라는 점을 명시 |
| 저장 처리 | 저장 성공/실패 분리 표시 |
| 이력 연동 | `body-comparison` 전용 상세/카드 표시 여부를 미리 정해야 함 |
