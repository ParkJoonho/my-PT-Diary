# 스펙 문서 관리 지침

작성일자: 2026-07-22

## 적용 범위

이 지침은 `docs/specs/`와 모든 하위 폴더 및 문서에 적용한다.

## 폴더 관리 방법

- 스펙 문서는 화면 또는 기능이 속한 도메인 폴더 아래에 둔다. 홈 화면 기능은 `docs/specs/home/` 아래에서 관리한다.
- 하나의 기능은 원칙적으로 하나의 Markdown 문서로 관리한다.
- 같은 기능을 서버·클라이언트·테스트 문서로 불필요하게 분리하지 않는다.
- 새 폴더나 문서를 만들기 전에 기존 문서에 포함할 수 있는지 먼저 확인한다.
- 파일명은 기능을 식별할 수 있는 영문 kebab-case를 사용한다.
- 요구사항과 구현 상태는 추후 요구사항 정의서나 QA 추적표로 옮길 수 있도록 표로 작성한다.
- 표에는 가능한 경우 요구사항 ID, 기대 동작, 현재 구현, 구현 상태, 근거 파일과 테스트를 포함한다.
- 코드에서 확인한 사실과 아직 구현되지 않은 기대사항을 명확히 구분한다.
- 문서 최상단에는 제목과 작성일자를 `YYYY-MM-DD` 형식으로 기록한다.

## 문서 업데이트 금지

- 사용자가 문서 작성 또는 업데이트를 명시적으로 요청하지 않은 경우 `docs/specs/`의 기존 문서를 수정하지 않는다.
- 코드 변경만 요청받은 경우 관련 스펙 문서를 자동으로 갱신하지 않는다.
- 구현과 문서가 다르더라도 사용자의 명시적 요청 없이 내용을 보정하거나 최신화하지 않는다.
- 문서 갱신이 필요해 보이면 파일을 수정하지 말고 사용자에게 차이와 갱신 필요성만 알린다.
- 사용자가 특정 문서와 수정 범위를 지정한 경우에만 해당 범위 안에서 업데이트한다.
